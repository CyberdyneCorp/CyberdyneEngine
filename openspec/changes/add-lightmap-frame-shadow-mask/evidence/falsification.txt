Mutations that turn this change's suites red. Development build (build/dev, Vulkan and Metal
renderers on), macOS 27.0, Apple M2 Max, Apple clang, Xcode 27.0. The device suite is
render.lightmaps_metal, which runs on the M2 Max's Metal device; render.lightmaps (Vulkan) compiles
and skips here, so nothing below claims a Vulkan result.

Each mutation was applied, the named targets rebuilt (for a cy/frame.slang edit, frame_spirv.h and
frame_msl.h regenerated first with src/rendering/pipeline/shaders/regenerate.py), the suites run,
every touched file restored and md5-verified, and the targets rebuilt from the restored tree. Under
each: the suites and the cases that failed. The runner is scratchpad tooling, not committed; each
block names the file and the edit exactly.

WHAT THE RECORD CORRECTS:

* b02 (a coarse padding texel owned by its LAST fine texel's chart instead of the nearest) SURVIVED
  its first run: in the one hand-drawn atlas the gap between rectangle C's charts fell where the
  last fine texel's owner and the nearest agreed for every texel a tap reaches. The suite gained
  'wherever the chart gap falls on the coarse grids, no tap reads the other chart', eight
  placements of the gap across a level-2 texel, and b02 is red.
* b06, b07 and l05 first failed to COMPILE (-Werror, an unused parameter), which proves nothing;
  they were rewritten to keep every parameter used, and the blocks below are those runs.
* r01, r02 and r03 first ran with a stale cy_build: c01 (the CLI ignores `cancel`) had rebuilt it
  and the first runner did not rebuild after restoring, so the real-tool Rust case failed for c01's
  reason. The runner now rebuilds after every restore; the blocks below are the clean reruns, and
  r02's commands-case failure in the first run did not recur.

* b01, b03 and b04 ran before the sweep case existed, against the suite's first three cases; b02
  is the mutation the sweep was added for.

THE FRAME WITH NO LIGHTMAP IS MAIN'S, BYTE FOR BYTE, on this device: render.lightmaps_metal (c)
holds it to references/lightmaps_absent_metal.png, captured by this suite on the M2 Max with main's
frame shaders (1b7373a5) before cy/frame.slang changed (md5 9e1f7003d58f51803b0e549dac82b03f,
identical over three runs). s08 changes only the no-lightmap path and turns (c) red.
