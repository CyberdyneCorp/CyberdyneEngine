# Design: M1 — Substrate

The specifications settle most of M1. This records what they leave open, plus the conventions M0
established that every agent in this milestone must build against.

## The M0 handoff — build against this, not against a guess

| | |
|---|---|
| Declare a target | `cy_add_module(NAME <n> LAYER <layer> ALIAS cy::<alias> TYPE <STATIC\|INTERFACE\|EXECUTABLE> SOURCES ... PUBLIC_INCLUDE_DIRS ... PUBLIC_DEPENDENCIES ... PRIVATE_DEPENDENCIES ...)`. A bare `add_library` fails the lint. |
| Layers | `core` 0 · `ecs` 1 · `servers` 2 · `backends` 3 (`platform/` too) · `scene` 4 · `runtime` 5 · `abi` 6 · `editor`/`tools` 7 |
| Header layout | `src/core/<mod>/include/cy/core/<mod>/*.h` public, `src/core/<mod>/src/*.h` private. Register the directory in `src/core/CMakeLists.txt`. |
| Fallible calls | `cy::Expected<T, Error>`; `return cy::fail(ErrorCode::NotFound, "…")`. Never throw, never RTTI. |
| Programmer error | `CY_ASSERT` / `CY_ASSERT_MSG` — compiled out in `Profile` and `Shipping`, so **no test may assert on assertion behaviour without checking the profile.** This exact mistake made the suite red in two profiles at M0. |
| Tests | `cy_add_test(NAME <n> KIND unit\|integration\|smoke SOURCES …)`. Test sources use `CY_TEST_CASE`; including doctest directly fails the build. |
| Diagnostics | Trace fields take a privacy classification as a required argument. There is no overload without one, and a path is a field, never a name. |
| Recipes | 45 exist. Add to the category file under `just/`, flat hyphenated names. |

**Explicit source lists, never globs.** M0's gate nearly mistook a file that was never compiled for
a passing check. M1 adds many files; a source not listed in a `CMakeLists.txt` is a silent no-op.

## 1 — Identity is assigned once and is not derived from anything

`core-type-system` requires persistent type and field identity with a committed manifest and a CI
gate. The open question is what an identifier *is*.

**Decision.** An identifier is an opaque number assigned on first sight and recorded in the
manifest. It is **not** a hash of the name, not a hash of the type, not an index, and not a content
digest.

Anything derived from a name changes when the name changes, which is precisely the event the
manifest exists to survive. A hash also silently collides; a counter cannot. The manifest is the
source of truth, the generator only ever appends to it, and removing a field writes a tombstone
rather than freeing its number for reuse.

**The gate is the point, not the manifest.** A renamed field with no tombstone fails the build with
a message naming the field, the old identifier and the fix. Test it by renaming a field.

## 2 — Reflection is generated by parsing, not by macros

The specification requires the generator use an established compiler frontend and keep the identity
model, metadata format and generated output engine-owned.

**Decision.** Parse annotated C++ with libclang. Emit generated C++ registered at startup. The
alternative — a macro DSL that declares types twice — was rejected by the specification before this
change and the reasoning holds: a declaration that can drift from the type it describes will.

**This milestone's named risk lives here.** Every contributor pays regeneration on every build for
the next ten milestones. The spike measures cold and incremental regeneration against a synthetic
type set an order of magnitude larger than M1's own, and confirms output is byte-reproducible. If
incremental regeneration is not fast, the answer is not to accept it — it is to change the approach
before anything depends on it.

## 3 — Access declarations before there is anything to schedule

`core-jobs-and-concurrency` requires parallel system execution be safe *by construction*: systems
declare `Read` / `Write` / `Exclude` and the scheduler derives parallelism from those declarations.

**Decision.** The declaration model and the conflict checker land in M1, exercised by synthetic
systems, even though no real system exists until M2. The checker rejects an overlapping write at
registration, not at run time.

Deferring this to M2 — when there is something to schedule — is the tempting order and the wrong
one. The property is *by construction*: it constrains how a system is written. Systems written first
and declared afterwards are written in a shape that may not admit a declaration.

## 4 — Conventions are tests, not comments

`core-math` fixes right-handed, Y-up, −Z forward; reversed-Z with a `[0,1]` range, depth cleared to
0, compared `GreaterEqual`; column-major matrices with column vectors; metres, seconds, radians.

**Decision.** Each is an executable test asserting the numeric consequence — that a perspective
matrix built by the engine maps the near plane to 1 and the far plane to 0, that a look-at down −Z
produces the identity rotation, that composing two transforms multiplies in the stated order.

A convention in a comment is a convention that gets violated by someone who did not read the
comment. The tests are what make M3's precision behaviour debuggable rather than mysterious.

## 5 — SIMD is an implementation detail with a scalar reference

**Decision.** One scalar reference implementation, always compiled and always tested, plus SIMD
paths selected at build time. Every SIMD path is tested against the scalar reference for
bit-identical results where the operation is exact, and within a stated tolerance where it is not.

`simulation-and-determinism` will later require a floating-point policy across platforms. A scalar
reference that is always present is what makes the eventual cross-platform comparison possible at
all, and it costs almost nothing now.

## 6 — The general allocator is a measurement, not a preference

`thirdparty-dependencies` states plainly that the general heap is an integration decided by
measurement and remains replaceable behind the allocator interface.

**Decision.** Build the interface, the domains and the budget tree first; measure the platform
allocator against one candidate on the engine's own allocation pattern; adopt one and record the
numbers in `design.md`. If the platform allocator wins, that is the result — no dependency is added,
and the interface makes the decision reversible.

## 7 — Chunked storage lands here, not in M2

Chunked component storage is in `core-memory-and-containers`, and M2's ECS is its first consumer.

**Decision.** The chunk allocator, layout and iteration land at M1 as memory machinery, with no
knowledge of components, archetypes or queries. M2 builds the ECS on top.

This is the split that keeps `ecs-core` about entities and archetypes rather than about memory. It
also means M2's cook-time flattening spike has something real to flatten *into*, which is what makes
that spike meaningful rather than theoretical.

## 8 — What M1 deliberately does not do

- **No ECS, no components, no queries, no archetypes.** M2. Chunk storage is memory, not an ECS.
- **No cooking, no streaming.** `core-assets-and-io` reaches Seed: identity, virtual filesystem,
  package format, async load. Cooked assets are M2; streaming under a residency policy is M6.
- **No renderer, no scene, no node.** M3 and M2.
- **No coroutine-based system scheduling.** Coroutines are the asynchronous model and land here;
  scheduling *systems* needs systems, which is M2.
- **No editor, no Swift, no ABI.** M4 and M5. The layer table already reserves their slots.

## 9 — Carried forward from M0

Two items M0 named and did not close. Both become M1's because the job system is what makes them
urgent:

**Sanitizers.** ASan, UBSan and TSan are wired and each proven to catch its class of bug, but no CI
job runs a suite under them, and LeakSanitizer reports the trace's process-lifetime thread rings.
M1 settles it: declare the intentional pooling where the detector can see it, then add the job. A
job system without TSan in CI is a data race waiting for a user to find it.

**Windows and macOS have never compiled.** Four M0 files are prose until CI runs. M1 adds
substantially more portable code, so the longer the first foreign build waits, the larger the
eventual diff. This is not M1's to fix, but M1 should not make it worse: no new
platform-conditional code without a stated reason.
